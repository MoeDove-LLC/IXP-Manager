# 邮件通知、恢复邀请与后台任务

默认关闭投递。启用时，在应用主机建立私密的 SMTP JSON 配置（`0600`，或更严格权限），通过 `ixp-manager --smtp-config /etc/moedove/smtp.json` 加载。配置不保存在 API 设置里，也不通过接口返回密码。

```json
{
  "enabled": true,
  "host": "smtp.example.net",
  "port": 587,
  "mode": "starttls",
  "username": "ixp@example.net",
  "password": "从密码管理器填入",
  "from": "ixp@example.net",
  "baseURL": "https://ixp.example.net"
}
```

生产模式支持 `tls`（隐式 TLS）和 `starttls`。必须成功验证服务器证书；STARTTLS 不可用时直接失败，不会降级后发送凭据或邮件。`baseURL` 为固定应用 origin，不从请求 Host/代理头生成安全链接。

仅隔离开发环境允许 `mode: "plain"` 与 `allowLoopbackPlain: true`，SMTP host 必须是字面 loopback IP 且不能配置用户名/密码；HTTP baseURL 也只允许 localhost/loopback。测试使用内存管道上的假 SMTP，不访问外部邮件服务。

## 持久发件箱

通知原因、收件人/正文快照及业务记录在同一份 `state.json` 事务中保存。邮件正文用实例 `security.key` 进行 AES-GCM 加密，关联消息 ID；恢复/邀请记录仅保存随机令牌的 SHA-256。管理员发件箱接口只提供收件人、主题、状态、次数和时间，不提供正文、密文、令牌或内部租约。

每条消息有稳定幂等键和 Message-ID；重试不会重新渲染正文或改变收件人。发送前先持久化一分钟租约，进程崩溃后租约过期可重试。投递失败自动重试最多 5 次，间隔 30、60、120、240 秒；过期安全链接不会投递，撤销的邀请、账号世代变化后的重置链接、已删除令牌的提醒也会在发送前停止。

SMTP 只能提供“至少一次”交付：若服务器已接收邮件、客户端却未收到确认，重试可能产生重复邮件。稳定 Message-ID 有助于识别重复，但不能宣称跨 SMTP 服务器恰好一次交付。

最多保留 2000 条发件箱记录，加密快照累计最多 32 MiB；终态记录保留 30 天，超出容量则拒绝新增。固定提醒任务每批最多生成 100 条，剩余批次稍后继续。发件箱满时不会悄悄丢弃待发安全邮件；管理员应检查容量和 SMTP 故障。错误信息固定为通用描述，不保存远端 SMTP 回显，防止回显的链接或令牌出现在界面和日志中。

## 配线通知

浏览器管理员可以对当前分配发送接通请求、停用请求、资料说明和 LOA 通知。端口状态变更、旧数据导入和历史恢复都不会自动发送邮件。管理员先查看当前分配及收件人，编辑主题和纯文本正文，选择实际附件，再预览并明确排队。关闭 SMTP 时仍可预览，排队返回不可用，不积压以后自动补发的通知。

To/CC/BCC 合计最多 10 个不重复的裸邮箱地址。默认建议当前成员 NOC（缺少时使用成员邮箱）和支持邮箱 BCC，也支持明确手填机房工程师等地址。选择联系人建议时绑定当前来源；手填地址始终标记为手工指定。BCC 只用于 SMTP 信封，保存在加密快照内，不进入 MIME 头、通知回执或审计内容；已有支持邮箱设置仍按原设置权限管理。

接通通知只适用于活跃成员的当前预留或待接通分配；停用请求适用于已接通或待停用分配。暂停、关闭或待启用的成员仍可在当前分配范围内接收停用和资料通知，便于完成拆线；这不重新启用成员或分配。LOA 通知必须选择活跃成员当前有效的已签发 PDF，接通通知可选择该 PDF；现有 LOA 规则在端口接通后将原预留授权标为失效，邮件不会把历史 PDF 重新标成有效授权。资料和停用通知可再明确选择最多 3 个当前成员可读附件。历史附件、工作人员私有附件和成员管理员专用旧文件不会因此扩大权限。附件真实字节进入加密 MIME 快照，最多 4 份、合计 2 MiB；不会用链接冒充附件。

预览令牌有效 10 分钟，并绑定当前登录会话、正文、地址、附件和分配上下文。任何编辑或上下文变化都需要重新预览。若排队响应丢失，可以显式重试同一份冻结请求，得到原回执，不新增发件箱记录。排队不代表已投递。邮件最多等待 24 小时，选择 LOA 时不会超过其到期时间；排队、投递交接前及手动重试都会复核当前管理员实体/安全代次、分配、来源地址、LOA 和附件权限版本。已经交给 SMTP 的消息无法在后续权限变化时撤回。

接口为 `/api/patching/ports/:id/notifications` 的 GET，以及其 `/review` 和 `/queue` POST。API Token、operator、viewer 和 member 不获得管理员邮件编写权限。备份须同时保留 State、实例密钥及现有 LOA/文档 blob；恢复不会把旧历史转换为新通知。

## 账号恢复与成员邀请

- 忘记密码对未知账号、投递关闭和有效账号返回同样的 `202` 响应；请求受 IP 限制和账号五分钟冷却限制。恢复令牌有效 20 分钟，单次使用且绑定账号世代。
- 密码重置不会关闭 MFA。开启 MFA 的账号还必须提供当前有效 TOTP 或一次性恢复码。完成后撤销所有会话和 API Token。
- 邀请只能由全局管理员或对应成员管理员发出，只能授予该成员的普通成员/成员管理员权限，不能授予全局员工角色。邀请有效七天，接受时重新检查邀请人的当前权限。
- 新账号通过邮件持有证明主动接受，并设置符合要求的密码。已有账号必须登录到邀请邮箱对应的账号，重新验证密码和 MFA 并提供 CSRF Token，之后才会增加成员关系。账号世代已变化的旧邀请失效；接受成员变更后要求重新登录。
- 安全链接使用 `/#reset-password?token=...` 或 `/#accept-invitation?token=...`，令牌不进入 HTTP URL/访问日志。前端取出令牌后清理 fragment，只在指定 POST 请求体中提交，不放入 localStorage。

发送关闭或无法通过邮件恢复时，使用已有的离线 `ixp-admin reset-password --password-stdin` 流程。备份须保留 `state.json` 和配套的 `security.key`；SMTP 配置在数据目录之外，由管理员单独备份其机密内容。

## 固定后台任务

Manager 显式启动 `StartBackground(ctx)`。关闭时先取消投递并等待 worker 退出，再关闭数据存储。调度状态、下一次运行时间和崩溃租约都持久化。

当前任务只有：

- `token-expiry`：提醒未来七天内到期的 API Token，按 Token ID/到期时间去重。
- `cleanup`：清理过期 Token、MFA 待验证登记、旧恢复/邀请记录、过期登录节流记录及旧发件箱记录。

管理员可排队立即运行这些固定任务，不能提供 shell、URL 或任意任务参数。没有自动批准路由策略、自动下发配置或自动调用外部集成。

验证：`go test -race ./internal/notify ./internal/app`。测试覆盖 TLS 降级拒绝、不可信证书拒绝、中文 MIME、不可变加密快照、崩溃租约和重试上限、MFA 恢复、令牌单次并发消费、邀请同意/权限复核、通知脱敏以及 worker 关闭顺序。
