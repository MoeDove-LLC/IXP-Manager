# 离线备份格式

`ixp-backup create` 获取与服务进程相同的排他锁，仅备份已有的有效实例。归档使用 tar+gzip，权限 0600。`manifest.json` v1 记录每个条目的相对路径、字节数和 SHA-256；白名单覆盖状态、密钥、引用的文档/LOA/策略、加密路由/配置/诊断工件、遥测快照/WAL及其精确引用的长期分区、sFlow快照/WAL、外部/设备发现与最新观察缓存。已明确清理的原文不再作为必需文件，但审阅元数据与审计仍被保留。归档不是加密容器，含加密状态及其密钥，应由操作员放入加密或受限备份存储。

恢复先在目标目录的同级私密临时目录检查全部条目。拒绝绝对路径、父目录路径、软/硬链接、重复条目、未知文件、散列不符、追加 gzip 成员和已有目标。验证完整后才发布新目录，不覆盖现有实例。总量上限8GiB、65536个文件、manifest上限32MiB；状态128MiB、附件25MiB、压缩长期分区16MiB、遥测WAL256MiB、sFlow数据文件128MiB，其他类别保留独立界限；密钥必须32字节。恢复不连接外部服务，不自动启动 HTTP 或路由守护进程。

升级前用新版 `ixp-backup verify --input snapshot.ixp-backup.tar.gz` 检查旧归档。它使用与恢复相同的解包、散列校验、数据关系检查和应用状态加载流程，校验完成后删除临时数据。可用 `--work-dir /path/to/scratch` 选择已有的临时目录父路径，默认使用系统的临时目录。临时磁盘需要容纳归档解包后的文件。`verify` 适合在决定切换版本前核对归档能否被新版读取。

长期统计、sFlow和旧统计批次使用只读预检，不为了备份而截断、整理或修复源。可恢复的末尾不完整WAL保留原字节，完整帧损坏仍拒绝。恢复在启动存储恢复逻辑之前核对分区引用，所以合法但未被快照引用的gzip文件也会拒绝；不能把manifest散列正确误当成业务引用正确。正常恢复随后可能执行当前保留策略。成员实体代次、密钥指纹、采样序列检查点一起保留，不能将资源JSON导入当作这些历史身份的恢复。

旧统计纳入 `legacy-traffic/legacy-manifest.json`（上限8MiB）及其引用的 `batches/<sha256>.json.gz`（各16MiB压缩上限）；排他锁与临时文件不纳入。旧统计审批及接收器审批随控制状态恢复，接收器逐包授权和socket回执不会恢复为有效运行证据。资源JSON导入则将启用接收器恢复为待审批，不能转移另一个实例的授权。

测试覆盖完整状态/附件/加密密钥往返、并发服务锁、目标覆盖拒绝、路径穿越、链接、压缩校验损坏、尾部追加和截断归档。当前没有在线快照或增量备份。
