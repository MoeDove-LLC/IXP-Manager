# Offline patch history and attachment migration

This path reads an explicitly supplied, offline table export and an explicitly
supplied filesystem snapshot. It does not read `.env`, connect to Laravel, a
database or object storage, send mail, configure devices, or restore old LOA
authorization. Prepare the source snapshot outside this tool.

Include `patch_panel`, `patch_panel_port`, `patch_panel_port_history`,
`patch_panel_port_file`, and `patch_panel_port_history_file`, plus the ordinary
member/rack/location/switch tables needed for their current foreign keys.

```sh
ixp-migrate --input offline-tables.json \
  --patch-bundle \
  --patch-files-root /srv/offline-snapshot/storage/app \
  --source-timezone Europe/Dublin \
  --output patching-import.tar.gz
```

`--output` must be a new file; bundles are mode `0600`, published atomically and
never written to stdout. `--strict` rejects any conversion warning before
publication. The default timezone is `unknown`: original datetime text remains
uninterpreted. An explicit IANA timezone records the operator's source-timezone
declaration. `DATE` columns remain date-only source values. Import timestamps
belong to the new system and are not reconstructed legacy event timestamps.

The file root is the old **default filesystem disk** snapshot root. For the
default local Laravel disk this is `storage/app`; an offline mirror of another
disk must contain the same logical keys. General `docstore` and
`docstore_customers` disks are different stores and are not patch attachment
roots. No remote-storage credentials or arbitrary per-file paths are accepted.

Patch files are opened only as:

```text
ROOT/files/ppp/<storage_location[0]>/<storage_location[1]>/<storage_location>
```

The saved key is the lowercase SHA-256-shaped **name key** generated by Laravel
from its original port ID and filename. It is not a content checksum and may
still name the old port after a move. The tool never recalculates it from the
current port. Every opened file must be a bounded regular file without symlink
components or hardlinks. Missing/changed content, mismatched declared size, or
nonconforming keys fail packaging. The actual content SHA-256 is calculated
while copying to a private staging directory.

The gzip/tar package contains a first `manifest.json` and exactly its declared
`files/current-<legacy-id>` / `files/history-<legacy-id>` regular entries. Limits
are 32 MiB for the manifest, 25 MiB per attachment, 1 GiB cumulative unpacked
data, 1 GiB + 8 MiB compressed input, and 8,193 physical entries. The target's
remaining document quota also applies. Symlink/hardlink/extension/special
entries, duplicate or noncanonical paths, extra/missing entries, bad digests,
truncated structures and concatenated/trailing streams are rejected.

An administrator uploads the file in Settings, or submits multipart field
`bundle` to `POST /api/import/patching` with a browser session and CSRF token.
The server validates and stages all content, rechecks current administrator
authority at commit, and publishes all inventory/snapshots/documents in one
state transaction. Failures leave no partial imported state; newly staged blobs
are removed. Existing IDs and repeated imports are rejected, never upserted.

Current inventory and old allocation snapshots are deliberately distinct:

* A complete, compatible panel becomes current inventory. Missing port rows,
  unsupported `Other` states, unresolved references, incompatible internal
  allocations or duplex relationships keep the **whole panel** in staff review;
  omitted old ports never become newly available slots.
* History rows preserve original labels, private notes, dates, IDs and duplex
  history references. They are allocation snapshots, not invented connect/cease
  events. `uploaded_by` is source text, not a Go account or permission grant.
* History attachments are always staff-only. A current nonprivate attachment
  can be read by a member only while its original direct-port customer, current
  allocation and member entity still match. A duplex slave's null customer does
  not inherit a file grant from its master. Release, reassignment and an A→B→A
  cycle revoke old member access across document listings, search, metadata,
  text, GET and HEAD downloads.
* Original private attachments retain their physical-port association for
  staff. They are not silently removed by release of tenant documents.
* Imported files and their managed folders are read-only snapshots. To create
  changed material or deliberately publish a different scope, upload a separate
  new document through the normal reviewed workflow.
* Old `loa_code` values are excluded. A PDF is an attachment, never an issued Go
  LOA. New LOAs require the normal current-reservation review and issuance flow.

Staff can inspect receipts, review panels, original snapshots and attachment
provenance at `GET /api/patching/legacy` and in the patching workspace. Source
notes remain plain text, not executable HTML. Review records do not silently
claim a live allocation.

Resource JSON export excludes these documents and history. Use the complete
offline backup/restore path to preserve file bytes, immutable source snapshots,
and their allocation/entity bindings together.

Focused validation uses synthetic JSON/files only:

```sh
go test -race ./internal/migrate ./cmd/ixp-migrate
go test -race ./internal/app -run 'TestLegacyPatch' -count=1
go test -race ./internal/backup -run 'TestLegacyPatchingBackup' -count=1
```
