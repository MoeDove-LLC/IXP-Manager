# Go 重写中的数据与边界

本文件解释当前实现的约束，功能覆盖仍以 MIGRATION.md 为准。控制面持久层目前仍是单进程 JSON 快照；大规模查询、分页、版本升级和更高容量存储仍需继续完善，不能把本轮功能测试当成全部生产验收。

## 控制面与观测分开

`internal/app` 管理组织、接入、权限与期望配置。资源写入在 Store.Update 中复制、校验并原子提交，引用冲突导致整批失败。网络请求不在事务锁内执行；返回后重新检查权限、当前数据摘要和版本。Store.Close 与写入互斥，关闭后不会执行迟到的修改；未知或不完整的持久化 schema 会拒绝加载，避免旧程序覆盖新字段。

通用资源的强 ETag 覆盖完整存储记录，使用实例密钥计算 HMAC，避免泄露私密字段的普通摘要。HTTP DTO 才携带 `_etag`，存储和数据导出不包含它。PUT/DELETE 在同一写事务内核对打开时的标识与当前操作者权限/安全代次；冲突时返回 412，不返回可能已撤权的最新记录。浏览器重新读取、明确核对合并后再提交，密码不会进入合并草稿。专用规则/配线/文档流程继续使用其各自的版本协议。

路由配置批准、配线状态变更、外部资料关联都不证明物理设备已经改变。前端明确区分配置、协议采样、人工双边协议和实际生效情况。设备发现和外部资料先形成审阅提案，不自动重写成员分配、IP、ASN、端口容量或线路状态。

## 采集数据的归属

计数器以十进制字符串保存，按 uint64 求差。采集器在读取设备之前取得服务器发出的归属版本；上传同时核对版本、时间、目标绑定和当前资源关系。重新分配、接口重新映射以及 A→B→A 的变化会更新版本并重置速率基线，不能用收到请求时的成员身份给历史数据重新贴标签。

成员查询还检查采样时的所有者和当前分配起点，并移除接口生命周期累计计数。SNMP 接口映射固定审核时的接口名称、类型、物理地址与设备引擎身份，避免重启后 ifIndex 复用造成错配。没有来源证据、归属版本不符、缺少数据或数据过期时展示未知，而不是虚构零值或在线状态。

Looking Glass 使用独立的类型化查询队列。服务端冻结当前 peer/router 和归属修订，绑定路由器的采集令牌领取短期租约；本地配置决定可执行文件、socket 和映射，不接受用户提供的命令。命令前后验证真实邻居/路由器身份，上传核对原查询、租约所有者及当前归属。结果保留 AS_SET、未知属性和截断信息；任务完成、表是否完整及样本新鲜度彼此独立。表级视图需工作人员权限、本机显式允许和可验证的原生身份。

路由快照在独立加密文件中保存，控制状态只留摘要和元数据；写文件后状态提交失败会回收未引用文件，让有效租约能够重试。成员读取同时检查采样时权限与当前关系，A→B→A 不重新暴露历史样本；工作人员读取已改变目标的历史时会显示过期。快照清理、元数据删除和完整备份各自保留必要的审计及引用检查。

长期计数器在同一个带序号 WAL 中生成原始点和多层汇总。不可变压缩分区与归属目录先落盘，快照原子发布精确引用，之后才截断 WAL；重放不会因 raw 已裁剪而重复累计旧记录。整数总量、覆盖、重置、回绕及均匀跨桶分配分别表达。多端口峰值来自共同完整桶，不相加各端口不同时刻的峰；Counter32 非字节指标不能以线速证明没有多次回绕，只提供有条件下界。

App 覆盖采集端自报的历史维度，并以实例密钥和成员创建身份绑定成员实体代次。成员历史可读本人当时拥有的记录，但不会继承复用 ID 或重新分配端口的旧数据；当前端口视图另外要求当前归属版本。首次记录这类历史前持久化密钥指纹，丢失或替换 key 不会静默创建新身份。单一来源选择避免同一端口被 SNMP 与不同路由采集器交替统计。

sFlow 是独立的采样估算链。有界 v5 parser 不上传原始包头、载荷、IP 地址或传输层端口。服务端按注册 exporter、交换机、真实 VLAN/接口和当前接入关系归属；只认可唯一成员入口，无法证明的样本保持未归属。估算、质量、成员实体与持久序列检查点由同一 WAL 提交；重复、冲突、乱序和未确认的重启候选不增加流量。每包只准备受影响行，避免热路径复制全库。

采样读 API 的目录和报表使用一致的成员/交换机授权；受限对端以别名表示，不能借历史统计查询无关成员或私密导出器。采集令牌的用户与绑定在每次请求核对，控制面只读映射按 Store 发布代次缓存；缓存不会免除授权。上传并发与读超时有界，正常映射冲突会关闭旧接收队列并重绑新包。UDP 来源和重启推断仍依赖受信监测网，不能被表述为设备密码学认证。

接收器审批冻结成员实体、接入、注册 MAC、接口及目标。只有持久摄入判定为新样本后，控制面才复核当前权限并签发最多5秒的样本索引授权；统计归属的物理端口回退不能扩大包头披露范围。采集器另需本地网段/端口/速率策略和显式启用，仅重编码获准净化包头，抑制全局统计和不透明记录。运行回执属于当前进程的本地 socket 证据，不能推断远端到达，授权版本不会覆盖旧回执版本。

旧统计以独立、不可变 gzip 批次和清单保存，保留原窗口、单位、精确值与未知值。文件提交后再发布 App 审批，失败时不授权成员；删除先撤销发布。成员查询同时要求批次审批、完整历史归属证明和实体代次，并使用成员专属别名。文件清单与接收器控制状态纳入离线备份，恢复在启动应用前核对引用；普通资源导入重置接收器审批。

## 外部测量与恢复

RIPE Atlas 使用固定提供者 origin 和本机私密 API key 配置。探针与目标由用户明确选择，提案冻结成员、VLAN、地址族和目标地址；默认私有，创建前审阅整个矩阵的样本与 credits 上界。审批、首次执行和恢复分开，过期审批只能重新认证后续批尚未尝试的余项；固定开始时间已过时不会自动改期。

每个收费创建先持久化独立意图和额度预留，再发外部请求。超时、响应不确定或回执持久化失败均保留不确定状态，不自动重发；通过原意图和目标的唯一匹配确认所有权后才能停止。矩阵按方向独立推进，结果保留多路径、丢包、探针错误和缺失 RTT，不用计划目标填充缺少的实际目标。已结束测量在有界宽限期继续读取晚到结果，不推断缺失样本为成功。

额度预留按独立小时桶保留，清理 run 或快照不能恢复已经预留的额度。原始响应、所有权回执与类型化结果使用独立加密文件及配额，完整备份保留引用、实例身份和账本。API key 配置另行保管；没有显式本地配置时，恢复实例不会自动联系外部 Atlas 服务。

## 审阅与不可变文件

路由配置、策略、外部提案、设备发现和 LOA 原文采用私密文件/不可变 blob，控制状态保存摘要和引用。路由配置额外使用 AES-GCM 加密并绑定版本 ID 与实际内容摘要；兼容的旧内嵌配置在启动时迁移，审批状态和内容校验和保留。读取核对类型、大小和完整性。摘要证明文件完整性，不证明外部来源可信；离线导入与真实提供者获取会明确区分。大型文件不应新增为热状态中的内嵌正文。

BGP 凭据单独加密保存，不进入通用资源、JSON 导出、审计或脱敏预览。密文绑定会话 ID、随机修订及路由器/成员/对端身份；更新与删除核对修订和目标摘要，删除保留修订，避免先删除再设置造成旧请求被接受。只有重新认证的管理员或操作员可变更凭据，平台渲染只接受明确兼容的字符和长度。公开审批标识是以实例密钥计算的 HMAC，不是明文配置 SHA-256；真实校验和仅随授权下载返回，避免脱敏配置加普通摘要成为弱密码猜测依据。

有容量上限的数据需要可使用的生命周期：待审阅内容不会被静默删除；已处理内容可由管理员按明确的保留操作清理原文，保留审阅元数据与审计摘要。备份的白名单同时覆盖新增文件空间，恢复前验证引用和完整性。

路由发布与 DNS/监测配置复用私密文件读写、原子发布和孤儿回收实现，但使用不同的目录和 AES-GCM 关联数据；同 ID/内容的密文也不能跨用途读取。规则与生成版本分别保存，规则修改核对修订，审批及下载重新比较当前规则和库存生成结果。最新批准版本及唯一匹配当前意图的批准文件受到保留保护；删除规则后可以显式清理其历史文件。

DNS 的已分配、已批准 serial 按反向区独立持久化。已有区必须提供当前序列基线；删除规则再创建也不能重置计数。审批只能推进已批准序列，下载只提供该区当前批准的 serial；资源导出携带已分配下限，完整备份额外保留全部计数与工件。达到 uint32 上限后明确停止，尚未实现自动 RFC 1982 回绕迁移。原生区文件校验不证明当前线上序列或上级委派已核对。

收集器的观察视图与授权 RIB 分开，BIRD/FRR 都禁止导出和内核安装。观察及 RPKI 重评估所需的预策略缓存采用包含过滤路由的接收上限；不能仅限制已接受路由。库存的可 ping、允许监测和活跃状态只控制生成范围，Nagios 探针仍必须依据实际、身份匹配且新鲜的观测，不能从期望状态推导健康。

BIRD 3 和 OpenBGPD 使用独立原生解析器，平台信息固定在审批版本中。BIRD 3 发布与恢复另外核对 daemon 主版本；OpenBGPD 看护通过固定私密 socket、Linux root parent 的可执行文件/目标参数/starttime 建立实例身份，并用 durable journal 做本机恢复。后者不是设备原生 confirmed-commit，也无法证明其他 root 管理员没有执行带外动态命令；独占实例和持续监督器是明确前提。原生解析与 mock 控制事务不替代实机验收。

## 身份、通知与令牌

浏览器使用 HttpOnly/SameSite 会话、Origin 和 CSRF 校验。成员角色始终按当前成员关系判断；成员 API 令牌固定创建时的组织。采集令牌另外绑定路由器或交换机，不能读取账号、修改系统设置或批准配置。

邮件正文和一次性链接加密后与业务原因一起提交，恢复/邀请记录只保存令牌摘要。发件箱不向 API 暴露正文、密文或租约。投递使用私密主机配置、验证 TLS、固定应用 origin 和有界重试；任务只运行注册的业务种类。测试不会向真实收件人发送邮件。

## 多交换网络

未绑定的旧记录属于兼容默认网络；显式基础设施相互独立。VLAN 编号按基础设施唯一，连接和整个 LAG 必须与交换机所属网络一致。移动相连资源使用一个事务完成。多网段逐一验证，IX-F 1.0 无法表示同地址族多个前缀时省略可选单前缀字段，不编造覆盖更大地址空间的聚合。

核心互联另用有界 typed bundle 保存两端逻辑接口和物理端点，不把管理成员归属当成租户访问权。聚合审阅 HMAC 覆盖模型及依赖端口、交换机和占用，端口选择也需核心专用 ETag。端口的 `coreReserved` 用途在拆除逻辑拓扑后继续保留；只有明确释放且无核心引用才能转为成员接入。旧未归组线缆保留占用，显式采用与聚合保存原子完成。

每次核心拓扑改变推进独立 bindingRevision 和相关端口 ownershipSince。SNMP 绑定摘要包含核心归属，当前观测和历史曲线只接受匹配的实际采样；读取文件后再次核对聚合修订，避免读到一半时归属已经改变。物理端口 Up 不推导协议健康，聚合流量按 A/B 两侧独立计算，缺少成员端口速率保留 null 与覆盖数。

`switch-core` 的 JSON 计划复用配置工具的加密不可变版本、审阅、批准及 profile 绑定下载；下载还绑定明确物理 switch ID。结构校验跨字段核对物理端口、逻辑聚合、地址、双栈邻居和 loopback，不声明已经通过厂商原生检查。原生适配、目标安装和撤回仍是独立待完成工作。
