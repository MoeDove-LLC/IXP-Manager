# 记住设备与保持登录

登录表单中的「记住此设备」是本人明确选择，默认关闭。未启用 MFA 的账号必须通过密码；已启用 MFA 的账号必须同时通过当前验证码或有效的一次性恢复码。密码验证阶段不会先生成记住设备许可。旧 PHP 的 remember cookie、明文 token 和 `is_2fa_complete` 标记都不迁移为可信凭据。

功能只在直连 TLS 或明确启用 `-secure-cookie` 的 HTTPS 反向代理部署中提供。持久 cookie 名称为 `__Host-moedove_remember`，固定 `HttpOnly`、`Secure`、`SameSite=Strict`、`Path=/`，不设置 Domain。前端不读取、复制或保存 cookie/校验值；只调用正常登录和恢复接口。

每次完整登录选择记住时产生一个独立随机设备标识和 256-bit 校验值。服务器只保存校验值摘要及有限元数据，绑定账号 ID、账号创建时间、安全 generation，以及当前密码/MFA/邮箱/角色和成员范围。IP 与 User-Agent 仅作本人辨认的标签，不是硬件指纹或授权来源。每个账号最多 10 个、实例最多 10000 个许可；到达上限需先不记住地登录，再明确撤销旧设备，不自动踢出其他设备。

许可硬过期为 30 天。恢复会轮换校验值、更新最近使用标签并签发新的普通 12 小时会话和 CSRF，但不会延长原硬过期时间。普通会话也关联来源设备：设备过期、撤销或账号安全条件改变后，相关会话不能继续访问。

## 接口合同

| 接口 | 行为 |
| --- | --- |
| `GET /api/setup` | 原有 `required`，新增 `rememberDeviceAvailable` 与 `rememberDeviceDays: 30` |
| `POST /api/login` | 原密码/MFA参数之外接受 `rememberDevice: true`；默认不记住；不安全传输下显式选择返回 400，设备满额返回 409 |
| `POST /api/session/restore` | 同源 JSON `{}`；成功返回现有 `{user, csrfToken}`；已有有效普通会话时直接返回且不轮换 |
| `GET /api/account/remembered-devices` | 本人 `{items, maxDevices: 10, hardExpiryDays: 30}`；每项仅含 `id, createdAt, lastUsedAt, expiresAt, ip, userAgent, current` |
| `DELETE /api/account/remembered-devices/:id` | 撤销本人指定设备与该设备衍生会话 |
| `DELETE /api/account/remembered-devices` | 撤销本人全部设备与其衍生会话 |

删除接口要求当前浏览器会话和 CSRF，返回 `{ok: true, signedOut: boolean}`。当前会话由被撤销设备创建时 `signedOut` 为 true；普通密码登录的会话可以保留。删除响应不写 Set-Cookie，避免迟到响应抹掉另一个标签页刚明确登录的新设备；旧 cookie 已在服务器失效。设备列表和恢复接口均不授权 API tokens，也不返回摘要或原始令牌。

恢复失败返回 401，绝不清 cookie，也不因为一个错误校验值撤销当前设备。最近 30 秒内的上一校验值只用于识别多标签页竞争，返回 `retrySession: true`，前端重新读取普通会话；它永远不能恢复登录。浏览器可用 Web Locks 串行化完整登录与启动恢复，且不得让旧失败响应覆盖新会话视图。没有 cookie 或 cookie 格式错误的启动请求不消耗共享 IP 的实际登录尝试额度。

完整密码及 MFA 登录成功后，会退役浏览器先前携带的许可。为了避免旧恢复响应迟到后重新带回先前账号，此清理步骤也识别最近 30 秒的上一校验值，仅用于撤销，不能用于认证。错误密码/MFA、错误旧校验值或过期旧校验值都不能执行此清理。

## 撤销、重启与备份

显式退出登录撤销当前设备及相关会话，并清浏览器 cookie。删除普通会话也撤销其来源设备，防止立即通过同一记住许可绕回来。密码修改、邮件或离线密码重置、MFA启用/停用、恢复码重新生成、账号删除/重建、管理员账号变更和「撤销其他会话」都会使旧许可失效。完成重新认证的当前会话可按原安全操作语义保留为普通会话；保留会话不会重新授予记住许可。

正常服务重启保留未过期的有效许可，内存普通会话仍需重新恢复。完整私密备份只包含摘要和元数据；`ixp-backup restore` 验证暂存目录后会清空记住设备许可，再发布恢复目录，防止旧备份重新激活备份之后已撤销的浏览器。账号、MFA、API token和业务数据保持原备份语义；恢复后需要本人重新完整登录并选择记住。

普通库存导出不包含记住设备状态。持久化校验拒绝重复设备标识、无效摘要、错误硬过期长度、超界数量或元数据。验证使用合成账号、离线只读源码/工具链和受限 scratch，不访问生产账号或外部邮件服务；具体回归结果独立记录，不扩大此前完整 App/Backup 测试的版本覆盖。
