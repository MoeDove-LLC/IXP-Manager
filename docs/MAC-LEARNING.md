# MAC 登记与学习对照

“地址分配 → MAC 登记与学习对照”读取指定交换机最近一次 SNMP FDB 观测，分别显示设备报告的学习记录和库存中已登记的地址。两者不自动同步。“本次未见”只表示当前有效观测没有对应项，不表示设备离线，也不证明 FDB 已完整采集。

只有动态学习的非零单播 EUI-48、唯一 VLAN、已审核的物理接口、当前有效成员接入可以申请登记。接口必须具有匹配的采集归属版本及设备身份；核心接口、聚合接口、未映射接口、多 VLAN FDB、过期或最近采集失败的数据均不能直接登记。同一观测在不同接入看到相同 VLAN/MAC 时显示冲突；不会选择第一条或允许人工按钮跳过歧义。LAG 的不同物理成员口若明确归属于同一个接入，不被当成不同成员。

管理员或操作员先审阅具体候选及后果，再提交登记名并确认。审阅最长一分钟，且不会超过观测的120秒新鲜期。观察文件摘要、库存、成员实体、VLAN、候选和截止时间一起参与实例密钥摘要。确认前重新读取当前权限与事务内库存；注销、会话撤销、重新采集、接口换代、成员变化或新增冲突都会拒绝旧审阅。409后保留登记名，刷新证据后重新确认。

登记只新增常规 `mac-addresses` 资源和审计证据，不改变接入所有者，不写交换机，也不启用路由配置。新登记会影响后续采样归属，并使相关接收器此前审批失效；接收器需要重新审阅才可继续获得逐包授权。手工资源写入和旧数据转换同样要求非零单播地址及同一个实际 VLAN 内唯一登记；不同基础设施中的独立 VLAN 不会因编号相同而混为一体。

当前学习来源是 SNMP FDB。旧 `macaddress` 表中的 sFlow 学习历史仍不自动迁入登记；持久 sFlow 学习候选、旧首次/末次学习历史及 OUI 厂商资料是另外的待迁移项。旧 `l2address` 才是已登记地址，转换规则见[旧接收器与登记 MAC 迁移](../cmd/ixp-migrate/SFLOW-RECEIVERS.md)。

接口：

- `GET /api/devices/mac-learning?switchId=...&offset=0&limit=100`：工作人员读取。API token 需要当前 `devices:read` 和该交换机绑定；成员不能读取原始学习目录。
- 可选 `candidateId` 会定位到候选所在分页；失效候选返回404。每页最多500条，登记对照最多2000条，返回 `registeredTotal/registeredTruncated`，完整登记仍在资源目录中查找。
- `POST /api/devices/mac-learning/review`：工作人员浏览器提交交换机、观察摘要和候选ID，取得审阅摘要及到期时间。
- `POST /api/devices/mac-learning/apply`：提交同一证据、审阅摘要、到期时间、登记名及明确确认。API采集令牌和只读用户不能自行批准采集结果。

FDB 仍是设备的报告，人工确认不是设备真实性或线路上身份的密码学证明。界面保留采集时间与安全模式，管理员仍需使用可信采集路径。这里的验证使用合成库存、实际本地HTTP链路与浏览器，不连接生产交换机。
