# 邮件列表偏好与导出

管理页面位于「交换中心设置」，个人页面位于「账号安全 → 邮件列表」。列表定义由管理员建立；所有登录用户只能修改自己的偏好，不能选择其他账号，也不能查看其他订阅者。

默认没有列表、没有订阅。列表名称、说明、列表邮箱及归档链接是向登录用户显示的资料。归档链接仅作为链接展示，服务器不抓取它。列表 key 和邮箱创建后不可更改；更换外部目标应建立新定义并重新取得用户选择。停用只暂停新订阅和同步导出，不会假称已从外部服务删除订阅者。已有偏好的用户仍可记录退订。

## 偏好和外部状态

保存偏好后，可用 `ixp-sync mailing-plan/apply/reconcile/status` 同步至 Mailman Core 3.3.10 REST 3.1。重复同步可使用 `mailing-watch`，由管理员首次审阅并授权固定来源、目标列表、周期和每轮变更上限。之后用户选择会在下一轮进入同步。遇到结果不确定、权限失效或目标列表重建时，worker 会持久停止，等待明确核对。控制台目前显示已保存的偏好，Mailman 的观测结果可通过 CLI 查看。[同步桥说明](../internal/mailingsync/README.md)

偏好绑定账号 ID、账号创建时间、具体列表和当时的邮箱。修改邮箱后，新邮箱不会继承旧选择，需要本人再次确认；旧邮箱保留为退订候选。删除账号或以相同 ID 建立不同实体，不会继承旧订阅。如果旧邮箱后来属于另一当前账号，该账号明确保存的新订阅优先于历史退订记录。

未选择的账号既不会进入订阅清单，也不会被自动当成退订清单。清单仅表达明确选择和失效绑定，不是用来替换外部系统的全部成员。外部同步不得删除清单之外的订阅者。

列表配置和个人选择都有独立修订检查。发生 `409` 时必须重新读取并核对；旧页面不能覆盖较新的选择。个人请求还必须包含页面刚显示的当前账号邮箱，防止邮箱在编辑期间改变后沿用旧决定。偏好不是成员组织的可转移属性，切换租户不改变账号本人。

## HTTP

所有接口要求登录；公开 IX-F 开关与本功能无关。修改要求浏览器会话和 CSRF。配置及订阅者导出仅管理员可用。

| 路径 | 方法 | 用途 |
| --- | --- | --- |
| `/api/account/mailing-lists` | GET | 本人当前邮箱、可见列表和偏好 |
| `/api/account/mailing-lists/{id}` | PUT | 本人选择，包含 `listRevision`、`preferenceRevision`、`email`、`subscribed` |
| `/api/mailing-lists` | GET / POST | 管理员读取 / 创建列表 |
| `/api/mailing-lists/{id}` | PUT | 管理员修改名称、说明、归档地址和启用状态，包含 `revision` |
| `/api/mailing-lists/{id}/export` | GET | 已启用列表的完整订阅 / 退订快照 |

修订为范围不超过 JavaScript 精确整数上限的 JSON 整数；客户端应原样回传。修改列表时不能提交 `key` 或 `email`，即使值未变。

自动化导出需要管理员显式创建的 `mailing-lists:read` 令牌。已有 `exports:read` 和 `resources:read` 令牌不会因此获得订阅数据；新令牌也不能修改配置或个人偏好。

以下原只读接口保留 JSON / 逐行文本表示，遵守相同管理员和专用令牌权限，`key` 来自当前列表定义：

- `/api/v4/mailing-list/subscribers/json/{key}`
- `/api/v4/mailing-list/subscribers/{key}`
- `/api/v4/mailing-list/unsubscribed/json/{key}`
- `/api/v4/mailing-list/unsubscribed/{key}`

这些兼容入口不接受旧 `X-IXP-Manager-API-Key` 授权方式。旧 PHP 偏好现通过独立 `--mailing-archive` 来源包迁移：管理员明确关联账号和列表，再由本人逐项审阅接受，不能据邮箱相同自动赋予订阅。入口位于设置页和「账号安全 → 邮件列表 → 旧邮件订阅迁移」，步骤见[旧偏好迁移](LEGACY-MAILING.md)。未选项保留为来源，可重新映射；已存在的当前邮箱选择不会被覆盖。外部列表内容不能当成新账号的自动同意。

完整导出包含固定列表身份、版本、已排序去重的两个地址数组、生成时间和内容校验和。校验和覆盖版本、列表身份和两个地址数组，生成时间不改变相同内容的校验和。停用列表返回 `409`，不会发出可能被误解为“删除全部成员”的空同步计划。

## 持久化与验证

定义、偏好和旧地址记录保存在私密 `state.json` 中，普通库存 JSON 导出不包含它们。离线 `ixp-backup` 保存并恢复完整状态；重启校验拒绝重复实体绑定、无效地址、缺少列表引用或超界修订，不会自动补造外部成功回执。

当前上限为 64 个列表、50000 个账号/列表偏好和 100000 个旧地址记录。旧记录用于撤回既有绑定，不能在未核对外部状态时静默删除以腾出容量。

验证覆盖 HTTP 权限、CSRF、并发选择、邮箱与实体变更、旧导出、备份恢复，以及从旧来源到本人接受的浏览器流程。在隔离的 Mailman Core 3.3.10 中，周期 worker 按同一份授权完成订阅和下一轮退订，保留无关成员，SMTP 捕获器未收到同步通知。新增订阅要求目标列表的管理员通知明确关闭。控制台同步回执与根据回执清理旧地址仍待接通。
