# 长期流量与采样分析

计数器统计与 sFlow 估算是两条独立数据链。计数器页面使用真实接口累计值的差分；sFlow 页面使用收到的抽样记录及采样率形成估算。两者不能相加为总量，也不代表精确计费或端到端转发结果。没有数据时保留 null/未知，只有真实连续观测到计数不变才显示零。

## 长期计数器

原始点仍最多保留 24 小时、每序列 2880 点、全局 100000 点。长期汇总在同一个摄入 WAL 中同步派生，不等待每天的任务，也不回看可能已经裁剪的原始数据。分层保留上限为 5 分钟/90 天、小时/400 天、UTC 日/3653 天；实际起点受数据开始时间、覆盖与磁盘配额影响。

归档使用私密、不可变的 gzip 分区。先写入并同步分区，再原子发布引用它们的快照，最后截断已提交 WAL；重启按序号跳过已经发布的记录。归档目录硬限额 2 GiB，已发布分区预算 768 MiB，其余留给原子替换。配额压力会优先清理最旧的细粒度数据，查询明确返回实际可用范围。

总量使用十进制整数文本，超过 JavaScript 精度范围也不丢位。只有相同来源、成员实体代次、归属版本、计数器 epoch、位宽及库存维度的相邻样本才连接。过长间隔、重置、缺失和歧义分别记录。跨 UTC 桶按均匀分配假设切分，最后一个片段获得整数余量，保证各层总量守恒。

单端口平均值基于有效观测时长；峰值是观测区间峰，不是瞬时峰。多端口组仅在同一个桶的所有预期端口均完整覆盖时给出平均值和峰值，不能相加各端口不同时间的最大值。部分覆盖仍保留已知总量，但不能据此外推完整组的速率。覆盖率按“端口 × 时间”计算，加入或退役端口也可能形成空档，不应直接当成采集器故障。

Counter32 包数、错误和丢弃不能从链路速率证明没有多次回绕。同 epoch 且未发现重置时保留模差分的条件下界，显示“至少 N”，精确总量与速率仍为未知。下界已经包含同桶的其它精确部分，不能再加一次。Counter64 差分不被库存名义速率裁切；软件接口交给设备的数据也不保证已在线路发出。数学、存储与限制见[统计引擎说明](../internal/telemetry/TRAFFIC.md)。

SNMP 使用 IF-HC 包计数，缺少时按方向回退32位；错误/丢弃保持 IF-MIB 的32位语义。Linux 读取实际 `rx_errors/tx_errors`、`rx_dropped/tx_dropped` 与接收组播，缺文件保持未知。Linux 总包数不冒充单播包数，接收组播也不冒充发送组播；定义依据[内核接口统计说明](https://docs.kernel.org/networking/statistics.html)。

## 来源与历史授权

每个端口只选一个计数来源。自动模式优先使用已审核 SNMP 映射；否则必须只有一个关联的路由采集器。存在多个候选时不混合它们，页面提供明确的来源选择与版本核对。显式来源失去接入关系后暂停，不阻止库存重新分配。来源变化推进采样归属并重新建立基线。

维度由服务端在摄入时冻结，包括成员实体代次、交换机、机架、机房、基础设施、接入及核心互联侧别。物理计数无法拆分 IP 地址族、VLAN 或成员对；共享端口的接入图可能包含其它 VLAN。核心互联必须分别选择 A/B，不能相加为吞吐量。

成员可查看当前所属端口和本成员的历史，历史包括曾用端口。端口转归后，原成员保留自己的已采集历史，新成员不会继承这些数值。成员 ID 删除再复用也不能重新授权旧实体的数据。缺少实体代次证据的旧记录仅工作人员可读；不会按今天的持有者补标签。实例 `security.key` 同时绑定这些历史标识，丢失或替换后不能静默生成新身份。

- `GET /api/traffic/catalog`：授权目标、指标、分辨率及来源状态。
- `GET /api/traffic/query`：`scope/id/metric/resolution/from/to`；核心互联另需 `side=a|b`。成员历史代次由服务端强制核对。
- `POST /api/traffic/source`：工作人员浏览器提交 `{portId,selection,expectedRevision}`，只改审阅过的来源。

查询使用 RFC3339，按 UTC 时间桶对齐并返回实际范围。总量字段保持字符串，速率只作浮点展示。更大的查询会明确要求缩小窗口，不返回假完整结果。

## sFlow

`ixp-sflow` 只在显式 `listen` 时打开配置中的 UDP 端点。私密配置限定源 IP、声明的 agent 地址、sub-agent 和控制面 HTTPS origin；令牌单独放在 `0600` 文件。解析有严格长度和层数限制，只上传安全元数据，不上传原始头、载荷、主机 IP、TCP/UDP 端口或用户字符串。UDP 允许列表不提供密码学认证，仍需要受信任的监测网络。

收包前获取映射，变更或临时失败时关闭旧 socket、丢弃旧包和缓冲，再重绑接收新包。服务端重新核验当前 exporter/switch/VLAN/接口/接入归属，不能接受客户端自报成员 ID。只统计可唯一确定的成员入口采样点；核心链路、出口重复观测、VLAN 冲突或未知接口保持未归属，避免同一包在多个观察点重复计入成员对流量。

绑定包含服务器 `issuedAt/expiresAt`。采集器用服务器时间及本地单调时钟估计收包时间，保守扣除往返耗时后决定重绑；不会因本地墙钟偏差延长授权。服务端拒绝先前收到的包取得新映射后再归属。这仍不提供精确线上抓包时刻，网络延迟与不对称会留下时间不确定性。

持久化流量、质量和序列检查点采用同一个 WAL。重复、冲突、回退与重启候选不会增加估算，映射变更或进程重启不清空检查点。重启仍是基于序列/uptime 的推断，不是设备认证。五分钟数据保留上限48小时，UTC日上限30天；无样本不会预填全矩阵零值。

成员读权限同时匹配每一侧的 ID 和实体代次；其它成员只有在当前目录规则允许且代次匹配时才显示名称，否则返回受限别名。私密 exporter、对端接入和全局质量不会进入成员报告。工作人员 API token 则明确绑定交换机，目录、数据、质量及保留元数据均受同一范围限制。`TCP179Samples` 只表示采样到相关 ACK 活动，不证明 BGP Established；其最后活动时间只由该类样本推进。

- `GET /api/sflow`：授权选择器、导出器配置与最近收包证据。
- `GET /api/sflow/query`：按收包整桶、AF、VLAN、exporter 和成员筛选有向估算。
- `GET /api/sflow/bindings?exporterId=` 与 `POST /api/sflow/ingest`：仅交换机绑定的 `sflow:write` 采集令牌。

接收器支持成员管理员申请、工作人员编辑、管理员重新认证审批、停用和删除。审批绑定目标地址、端口、成员实体、接入、VLAN、已核对的物理接口和注册 MAC；相关库存变化后必须重新审阅。逐包转发必须匹配审批中的导出器和实际物理入口/出口；只知道目的 MAC、出口未知或仅有远端连接归属时，不扩大转发范围。接收计划/pretag 仅用于检查和外部适配，本身不授权发送。

实际转发要求采集器显式使用 `listen --forward`、私密本地目的网段/端口与速率限制，以及同时具备 `sflow:write`、`sflow:forward` 和具体交换机范围的令牌。控制面只给刚刚接受的新包签发最长5秒、绑定当前接收器版本和具体样本索引的授权。成员只收到获准 FLOW 的净化包头；应用载荷、CNTR、未知厂商记录和全局源统计不转发。输出是独立 relay 流，不是原始抓包或完整流量副本。

停用立即停止签发新授权；已发出的短期授权和在途 UDP 无法撤回。页面分别展示授权和本地 socket 回执，回执不证明远端收到，进程重启后运行证据恢复为未知；失败不会重发旧 UDP 包。CLI、本地策略、裁剪范围和恢复细节见[sFlow 说明](../internal/sflow/README.md)。[旧接收器转换](../cmd/ixp-migrate/SFLOW-RECEIVERS.md)会重置审批；[SNMP FDB学习审阅](MAC-LEARNING.md)不自动把观测变为登记。sFlow学习候选持久化、旧学习历史及生产流量验证仍待完成。

## 备份和旧数据

离线完整备份纳入所有被快照引用的归档分区、归属目录、WAL、sFlow 快照/检查点，以及旧统计批次和接收器审批状态。只读预检不修复源文件。恢复先验证引用，再运行正常恢复规则；不把未引用分区偷偷纳入数据。备份总上限提高到 8 GiB、65536 个文件，清单上限32 MiB，单文件另有独立限制。私密密钥必须一起恢复。普通资源导入与完整备份不同：导入的启用接收器回到待审批状态，不能携带另一个实例的批准权限。

“旧统计”页与 `ixp-traffic-import` 支持旧 `traffic_daily`、`traffic_daily_phys_ints`、`p2p_daily_stats` 表 JSON 和 RRDtool xport JSON/XML。原始值保持十进制精度，null/NaN 保留未知，旧 MRTG/PhysInt 日标签不推断为自然日，重叠滑窗不相加；RRD rate 保持原速率和窗口，不冒充累计量。页面预览不保存，导入要求精确摘要、管理员重新认证和窗口确认。

默认仅工作人员可读。对成员发布还需要覆盖完整窗口的显式历史归属证据、当前成员实体代次和单独确认；不会用今天的端口所有者替代历史证明。成员只看到自己的行和不透明批次别名。离线 CLI 导入不会自动取得页面发布审批。每次查询选择一个批次，不跨来源、周期或重叠窗口汇总；删除先撤销成员发布，再清理文件。格式和原生 RRD 导出步骤见[旧统计迁移说明](../internal/traffic/LEGACY.md)。

本地验证使用合成库存、原生 RRDtool fixture、隔离 UDP 和浏览器，没有采集真实设备或向生产成员目标发送数据。
